# AGENTS.md — bringing an LLM up to speed on VoiceLevel

Orientation for an AI assistant (or a new human) picking this project up cold. Read this
before proposing changes. `CLAUDE.md` holds the short command reference; this file explains
the *why*, and the traps.

---

## 1. What this is

An **attenuation-only automatic microphone leveler** for live sound: a virtual fader that
only ever moves down from unity, steered towards a target level at a dB-per-second speed,
frozen while the talker pauses, and parkable at a learned position. Rust on
[nih-plug](https://github.com/robbert-vdh/nih-plug), shipping as VST3 and CLAP plus a
standalone app. Public repo, GPL-3.0 (forced by nih-plug's VST3 bindings — see §5).

## 2. The two rules that matter most

**It never applies gain.** Unity is the ceiling. The whole point of the product is that it
cannot cause feedback, so nothing may add a path that raises gain above 1.0 — not a makeup
control, not a "recover above unity" option, not a smoothing overshoot. The test
`output_never_exceeds_input_sample_for_sample` pins it; keep it green.

**It has zero latency.** No look-ahead, no internal buffering beyond the host's block, no
oversampling. `initialize` reports 0 samples and pluginval checks it. If you reach for
look-ahead to fix a problem, stop and solve it another way — the lag belongs on the fader's
*movement*, never on the audio.

## 4. How it actually works

Two detectors run on a **100 Hz high-passed** copy of the input (plosives, handling noise and
rumble must not pull the fader down):

- a **fast RMS** (10 ms) that answers "is anyone talking right now?" — it drives the hold
  gate and the meters;
- a **slow, gated RMS** (`Averaging`) that only integrates while the gate is open, so it
  measures the level *of the speech*, not of speech and pauses together. The fader is steered
  by this one: `wanted = clamp(speech − target, 0, range)`.

The fader slews towards `wanted` at `Speed` (down) or `Recovery` (up), per sample, and is
applied as one gain to every channel; on stereo the louder channel steers. The gate is why
"Hold below" and Learn behave sensibly through pauses — with a single slow detector the
decay tail after every pause diluted the Learn measurement and blurred what the threshold
meant. Do not fold the two detectors back into one.

**The fader position is persisted state, not a host parameter.** nih-plug's audio thread
cannot set parameters, and the fader is written by the audio thread (Auto, Learn commit),
by the editor (Fixed-mode drag) and by the host (state restore). It lives in
`VoiceLevelParams::fader_db` as `#[persist] Arc<AtomicF32>`; `process()` loads it before
applying settings and stores it back only if it moved, which is what keeps a Fixed-mode
drag from being clobbered mid-block.

**Learn is the third value of the `Mode` enum** for the same reason: the audio thread
commits the measurement when it sees the mode leave `Learn` (to Fixed or Auto), so a host
with only generic parameter UI can drive it. The editor's Learn button sets Learn, then
flips to Fixed after 5 s of *gated* speech or 30 s of wall clock — it waits 250 ms before
trusting the published learn progress because the audio thread needs a few blocks to reset
its counters.

## 5. Licensing

nih-plug is ISC, but its VST3 bindings (`vst3-sys`) are GPLv3, so a VST3 build is GPLv3
and the crate is `GPL-3.0-or-later`. This differs from the MIT posture of most of the fleet
and is not a mistake; `ATTRIBUTIONS.md` (generated) says so.

## 6. Release plumbing and traps

- `cargo xtask bundle-universal voicelevel --release` needs both Apple triples installed
  (`universal-apple-darwin` is a bundling target, not a rustup one). CI's macOS job asserts
  every Mach-O in the output is fat and counts them — a `find` that matched nothing must
  fail, not pass.
- The standalone's `-l` flag takes the layout **index** (1 = Mono, 2 = Stereo), not a name,
  and the CoreAudio backend refuses a device whose channel count differs from the layout.
- `clap-validator` fails four tests on **every** nih-plug plugin (nih-plug commit de42101):
  `state-invalid-random` and the three `state-reproducibility-*` rescan checks. They are in
  nih-plug's CLAP state-load wrapper and reproduce on its own `gain` example. Cite them as
  upstream; do not chase them here.
- Windows on Arm is `continue-on-error` in the matrix because nih-plug's own CI never builds
  it; a failure there must not hold the release.
- The About window's facts (`about_data.rs`) come from the website's `projects.json` via
  sync-about. A changed hook or guide URL is edited THERE, then synced.
- Egui's `-0.0` formatting: `format!("{:.1}", -0.0_f32)` prints `-0.0`, which is why
  `fmt_att` special-cases zero. Keep it.

## 7. Verifying a change

`cargo test` for the leveler; `pluginval --strictness-level 10 --validate VoiceLevel.vst3`
(pluginval.app is a fleet tool); and for anything audible, the standalone on a loopback
device with synthesised speech — `say -o speech.aiff "…"` played into a virtual device with
`ffmpeg -f audiotoolbox`. GUI logic that only a click exercises (the Learn auto-stop, the
Fixed-mode drag) has been reviewed, not click-tested; say so when you touch it.
